## Mason v0.1.5

修复 v0.1.4 上部分用户遇到的**启动即崩溃**问题，同时把安装包体积压回 100MB 以内。

### 🐛 修复

- **内置 CAD 引擎启动即崩溃（v0.1.4 回归）**
  部分用户升级到 v0.1.4 后一打开就报「Python CAD 引擎已退出」，无法渲染任何模型。

  原因：v0.1.4 为修复打包问题，把 build123d 从 0.12.0 降到了 0.11.1，而 0.11.1 丢失了 0.12.0 中对非法字体文件的 `TTLibError` 保护。build123d 在启动导入时会扫描系统字体目录，只要 **`C:\Windows\Fonts` 或用户字体目录里存在一个扩展名为 `.ttf`、内容却不是字体的文件**，导入即抛异常，引擎进程直接退出。

  该问题与下载、安装、网络均无关，纯属依赖版本差异——v0.1.3 用的正是 0.12.0，所以从未出现。

  修复：
  - 依赖恢复为 **build123d 0.12.0**，同时继续锁定 **cadquery-ocp-novtk 7.9.3.1.1**
  - CI 与本地环境构建脚本同步该组合，避免版本再次漂移

### 🔧 改进

- **引擎错误诊断增强**
  引擎异常退出时不再只显示一句笼统提示，而是直接给出**引擎绝对路径、日志路径和日志尾部的真实 traceback**，截图即可定位问题。报错遮罩支持多行滚动，长信息不再被截断；同时移除了对内置引擎有误导性的 `pip install` 提示。

- **安装包体积回落至 93.4MB**
  内置环境里 `threejs_materials` 的 67 个 PNG 法线贴图（85.6MB）只服务于 three.js 材质渲染，几何建模与 STL/STEP 导出完全不涉及，现于构建时统一裁剪；并清理 `__pycache__` 与重复 DLL。

  | 版本 | 内置环境 | Windows 安装包 |
  |------|----------|----------------|
  | v0.1.4 | 491 MB | 99.1 MB |
  | 本次 | 461.6 MB | **93.4 MB** |

### 📦 安装包

| 平台 | 文件 |
|------|------|
| Windows | `Mason-windows-x64-setup.exe`（推荐）/ `Mason-windows-x64.msi` |
| macOS (Apple Silicon) | `Mason-macos-aarch64.dmg` |
| Linux | `Mason-linux-amd64.deb` / `Mason-linux-x86_64.rpm` |

> 内置 Python 几何引擎随安装包分发，无需手动安装依赖。若从 v0.1.4 升级，建议先卸载旧版本再安装。
